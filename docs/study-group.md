# LipSum 스터디 그룹 기능 명세서

---

# 1. 기능 개요

LipSum의 스터디 그룹 기능은 같은 관심사와 목표를 가진 사용자들이 함께 학습하거나 프로젝트를 진행할 수 있도록 지원하는 커뮤니티 기능입니다.

사용자는 직접 스터디 그룹을 생성하여 팀원을 모집할 수 있으며, 다른 사용자의 그룹에 참가 신청을 보내 함께 학습하거나 협업 프로젝트를 진행할 수 있습니다.

## 주요 목적

- 같은 기술 스택을 공부하는 사용자 간 협업 지원
- 프로젝트 기반 팀 빌딩 활성화
- 개발자 간 네트워킹 및 커뮤니티 형성
- 장기적인 학습 그룹 운영 환경 제공

# 2. 주요 기능 상세

---

## 2.1 그룹 생성

사용자는 새로운 스터디 그룹을 생성할 수 있습니다.
그룹 생성 시 생성자는 자동으로 해당 그룹의 리더(LEADER) 권한을 부여받습니다.

### 기능 설명

- 스터디 그룹 이름 입력
- 그룹 설명 작성
- 기술 스택 태그 등록
- 공개 여부 설정
- 최대 인원 설정

### 요청 API

`POST /api/studies/groups`

### Request Body

```json
{
  "name": "스프링 스터디",
  "description": "백엔드 심화 학습 스터디",
  "techTags": "spring,java,jpa",
  "visibility": "PUBLIC",
  "capacity": 10
}
```

### 필드 설명

| 필드명      | 타입   | 설명                         |
| ----------- | ------ | ---------------------------- |
| name        | string | 그룹 이름                    |
| description | string | 그룹 설명                    |
| techTags    | string | 기술 태그                    |
| visibility  | enum   | 공개 여부 (PUBLIC / PRIVATE) |
| capacity    | number | 최대 인원 수                 |

### 응답

- 그룹 UUID 반환
- HTTP 201 Created 상태 코드 반환

---

## 2.2 그룹 검색 및 조회

사용자는 현재 모집 중인 스터디 그룹을 검색하고 조회할 수 있습니다.

### 기능 설명

- 그룹 이름 검색
- 그룹 설명 기반 검색
- 기술 태그 검색
- 모집 상태 필터링
- 공개 여부 필터링
- 페이지네이션 지원

### 요청 API

`GET /api/studies/groups`

### Query Parameter

| 필드명     | 설명                   |
| ---------- | ---------------------- |
| keyword    | 그룹 이름 및 설명 검색 |
| techTags   | 기술 태그 검색         |
| status     | OPEN / CLOSED          |
| visibility | PUBLIC / PRIVATE       |
| page       | 페이지 번호            |
| size       | 페이지 크기            |

### 응답 데이터

```json
{
  "groupUuid": "string",
  "name": "React 프로젝트 모집",
  "description": "프론트엔드 협업 프로젝트",
  "techTags": "react,typescript",
  "visibility": "PUBLIC",
  "status": "OPEN",
  "capacity": 5,
  "ownerUuid": "string",
  "ownerCustomId": "taeho",
  "memberCount": 3
}
```

## 2.3 그룹 상세 조회

사용자는 특정 스터디 그룹의 상세 정보를 조회할 수 있습니다.

### 기능 설명

- 그룹 상세 정보 조회
- 현재 참여 인원 조회
- 모집 상태 확인
- 방장 정보 조회
- 현재 사용자의 가입 여부 확인

### 요청 API

`GET /api/studies/groups/{uuid}`

### 접근 제한

| 그룹 상태 | 접근 가능 여부                        |
| --------- | ------------------------------------- |
| PUBLIC    | 누구나 조회 가능                      |
| PRIVATE   | 그룹 멤버 / 방장 / 관리자만 조회 가능 |

---

## 2.4 그룹 가입 신청

사용자는 원하는 스터디 그룹에 참가 요청을 보낼 수 있습니다.

### 기능 설명

- 모집 중인 그룹에 참가 신청 가능
- 이미 가입된 경우 신청 불가
- 승인 대기 상태인 경우 중복 신청 불가
- 모집 마감(CLOSED) 상태에서는 신청 불가

### 요청 API

`POST /api/studies/groups/{uuid}/join`

### 처리 흐름

```text
사용자 참가 신청
→ 요청 상태 PENDING 저장
→ 방장이 참가 요청 확인
→ 승인 또는 거절 진행
```

### 예외 처리

| 상황             | 처리         |
| ---------------- | ------------ |
| 이미 가입된 경우 | 409 Conflict |
| 이미 신청한 경우 | 409 Conflict |
| 모집 마감 상태   | 신청 불가    |

---

## 2.5 참가 요청 조회

방장은 현재 대기 중인 참가 요청 목록을 조회할 수 있습니다.

### 요청 API

`GET /api/studies/groups/{uuid}/requests`

### 응답 데이터

```json
[
  {
    "userUuid": "string",
    "status": "PENDING",
    "requestedAt": "2026-05-14T08:35:53.415Z"
  }
]
```

### 접근 권한

- LEADER
- ADMIN

---

## 2.6 참가 요청 승인

방장은 특정 사용자의 참가 요청을 승인할 수 있습니다.

### 요청 API

`POST /api/studies/groups/{uuid}/requests/{userUuid}/approve`

### 처리 결과

- 사용자가 그룹 멤버로 등록됨
- memberCount 증가
- 요청 상태 APPROVED 처리

---

## 2.7 참가 요청 거절

방장은 특정 사용자의 참가 요청을 거절할 수 있습니다.

### 요청 API

`POST /api/studies/groups/{uuid}/requests/{userUuid}/reject`

### 처리 결과

- 요청 상태 REJECTED 처리

---

## 2.8 참가 요청 취소

사용자는 본인이 신청한 참가 요청을 취소할 수 있습니다.

### 요청 API

`DELETE /api/studies/groups/{uuid}/requests/my`

### 기능 설명

- 승인 대기(PENDING) 상태에서만 취소 가능
- 이미 승인된 요청은 취소 불가

---

## 2.9 모집 상태 변경

방장은 그룹의 모집 상태를 변경할 수 있습니다.

### 기능 설명

- OPEN → 모집 가능
- CLOSED → 모집 마감

### 요청 API

`PATCH /api/studies/groups/{uuid}/status`

### Request Body

```json
{
  "status": "CLOSED"
}
```

### 상태 정의

| 상태   | 설명           |
| ------ | -------------- |
| OPEN   | 참가 신청 가능 |
| CLOSED | 참가 신청 불가 |

### 권한

- LEADER
- ADMIN

---

## 2.10 그룹 멤버 조회

그룹의 현재 멤버 목록을 조회할 수 있습니다.

### 요청 API

`GET /api/studies/groups/{uuid}/members`

### 응답 데이터

```json
[
  {
    "userUuid": "string",
    "customId": "taeho",
    "role": "LEADER",
    "joinedAt": "2026-05-14T08:35:53.416Z"
  }
]
```

### 역할(Role)

| 역할   | 설명      |
| ------ | --------- |
| LEADER | 그룹 방장 |
| MEMBER | 일반 멤버 |

---

## 2.11 멤버 강제 탈퇴

방장은 특정 멤버를 그룹에서 강제로 탈퇴시킬 수 있습니다.

### 기능 설명

- 비정상 활동 사용자 관리
- 그룹 운영 질서 유지

### 요청 API

`POST /api/studies/groups/{uuid}/kick`

### Request Body

```json
{
  "userUuid": "user-uuid-1234"
}
```

### 권한

- LEADER
- ADMIN

---

## 2.12 그룹 탈퇴

사용자는 현재 가입 중인 그룹에서 탈퇴할 수 있습니다.

### 요청 API

`DELETE /api/studies/groups/{uuid}/leave`

### 기능 설명

- 일반 멤버는 자유롭게 탈퇴 가능
- 방장은 바로 탈퇴 불가
- 리더 권한 위임 후 탈퇴 가능

### 예외 처리

| 상황             | 처리           |
| ---------------- | -------------- |
| 방장이 탈퇴 시도 | 리더 위임 필요 |

---

## 2.13 리더 위임

현재 방장은 다른 멤버에게 그룹 리더 권한을 위임할 수 있습니다.

### 요청 API

`PATCH /api/studies/groups/{uuid}`

### Request Body

```json
{
  "leaderUserUuid": "user-uuid-1234"
}
```

### 처리 결과

- 기존 방장 → MEMBER 변경
- 대상 사용자 → LEADER 변경

### 권한

- 현재 LEADER만 가능

# 8.1 스터디 그룹 목록 화면 (List Page)

## 1. 모집 상태 표시 (OPEN / CLOSED)

사용자가 가장 먼저 확인하는 핵심 정보입니다.
현재 참여 가능한 그룹인지 직관적으로 확인할 수 있어야 합니다.

### 추천 UI

- OPEN → 초록색 배지
- CLOSED → 회색 또는 빨간색 배지

### 예시

- `[모집중]`
- `[모집마감]`

---

## 2. 현재 인원 / 최대 인원 표시

가입 가능 여부를 빠르게 판단할 수 있도록 제공해야 합니다.

### 예시

- `3 / 5명`
- `8 / 10명`

### 추천 UX

- Progress Bar 형태 시각화 권장

---

## 3. 기술 태그 표시

스터디 탐색 및 검색에서 가장 중요한 요소 중 하나입니다.

### 예시

- `#React`
- `#Spring`
- `#TypeScript`

---

## 4. 그룹 제목 및 한줄 설명

목록 화면에서 가장 중요한 콘텐츠 영역입니다.

### 예시

**React 사이드 프로젝트 팀원 모집**
프론트엔드 / 백엔드 협업 프로젝트 진행 예정입니다.

### 추천 UX

- 설명은 1~2줄만 노출
- `ellipsis(...)` 처리 권장

## 5. 방장 정보 표시

그룹 생성자를 확인할 수 있어야 신뢰감을 줄 수 있습니다.

## 6. 공개 여부 표시
